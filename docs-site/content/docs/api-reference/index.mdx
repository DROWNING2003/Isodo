# API 参考

接口页面由公开 OpenAPI 契约生成，按开发任务分组。网页登录回调、会话管理和 API Key 管理属于账号控制接口，见[认证指南](/docs/guides/authentication)。

## 接口分组

| 分组 | 解决的问题 |
| --- | --- |
| 沙箱管理 | 创建、查询、修改名称、启动、停止和删除沙箱 |
| 应用访问 | 获取沙箱应用入口，以及供客户端打开的应用链接 |
| 命令执行 | 在运行中的 Guest 执行有超时和输出上限的非交互式命令 |
| HTTP 端口预览 | 管理 Guest 端口公开性与私有授权，转发 HTTP、WebSocket 和 SSE |
| 文件 | 上传、下载、创建目录、Stat、分页列目录、Remove 和 Move |
| 安全连接 | 管理持久注入规则；读取规则材料属于敏感操作，需满足该端点的授权条件 |
| MCP 市场 | 官方与自定义 MCP 的收藏、连接及沙箱绑定 |
| Skill 市场 | Skill 制作、收藏及远程沙箱应用 |
| Agent 配置 | 账号级配置文档与沙箱应用选择；使用交互式会话授权 |
| 模板管理 | 查看系统与个人模板、修改元数据、设置可见性和派生已有版本 |
| 模板构建 | 提交构建配方、查询构建状态 |
| 模板版本与标签 | 将可变 tag 解析或指向不可变的 Ready build |

## 命令执行与端口预览

[`RunSandboxCommand`](/docs/api-reference/endpoints/RunSandboxCommand) 接受 argv 数组，需提供 `Idempotency-Key`；API Key 需要独立 `sandboxes:execute` 权限。HTTP 200 后仍需检查 `exit_code` 和输出完整性。

[`CreateSandboxPreview`](/docs/api-reference/endpoints/CreateSandboxPreview) 接受 Guest 端口，API Key 需要独立 `sandboxes:preview` 权限。未显式配置的通用端口默认 `public`，直接打开 `url`，无需 Token/Cookie；切换 `private` 后匿名请求返回 401，浏览器通过 `authorization_url` 获取短期授权。私有授权五分钟内有效，生命周期变化会提前撤销。管理端口 31024、31080、38080 及旧端口 1024、1080、8080 始终禁止通用预览；T3 工作台鉴权保持独立。

从创建远程沙箱到启动 Python HTTP 服务的完整示例，见[HTTP 服务预览指南](/docs/guides/http-port-preview)。

## 在线调试命令

服务器选择 `https://api.drowning.top:18443`，不要将文档域名当作 API 地址。沙箱必须处于 running，API Key 需具备 `sandboxes:execute`。每个新请求使用新的 `Idempotency-Key`，相同请求的重试保留原值。

切到 JSON 请求体，先执行：

```json
{"argv":["/bin/ls","-la","/workspace"],"cwd":"/workspace","timeout_seconds":30}
```

`argv[0]` 是可执行文件，其余元素是参数；`cwd` 是工作目录。重定向、管道等 Shell 语法必须显式启动 Shell：

```json
{"argv":["/bin/sh","-lc","echo waw >> qwe.txt"],"cwd":"/workspace","timeout_seconds":30}
```

不要把整条 Shell 命令放进单个 `argv[0]`，也不要把 `ls` 填入 `cwd`。无需环境变量时移除调试器生成的 `property1` 等占位内容。

## 模板创建与构建

`POST /v1/templates` 只创建模板记录，保存名称、描述和可见性。它不会执行命令，也不会产生可以启动沙箱的镜像。

`POST /v1/templates/{templateID}/builds` 是另一步：提交 `source_build_id`、可选的 `commands` 和 `publish_tag`，登记异步构建任务。配方中的命令使用 argv 数组；需要 Shell 时应显式传入 `/bin/sh` 等可执行程序。

当前公开配方仅接受已有 build 作为来源，没有 Docker/OCI 镜像、Dockerfile 或本地文件上传字段。服务端已有 Registry、队列、状态转换与 Worker 框架；当前生产入口尚未接通执行配方的 Builder，不能将返回 `202` 视为构建已经能够完成。管理员构建、验证和发布系统工件的工具链与此用户构建接口是两条不同流程。本地 Node 另有模板目录和 Lima 命令构建接口，供桌面端使用；它没有接入这里的云端 Build 队列，也不是 Docker 镜像导入接口。

模板、构建和标签的关系是：一个模板可以有多次构建，tag 指向其中一个 Ready build，创建沙箱时将选择固定到具体 build。模板元数据存在，并不代表已有可运行版本。

## 认证与客户端

公开接口需要认证，支持浏览器会话 Cookie、Casdoor Bearer Token 或 API Key。API Key 通过 `X-API-Key` 请求头发送；各端点的具体权限与响应以端点页面为准。

仓库已有生成的 HTTP 请求函数和 App 内部 SandboxClient；生成的公开客户端包含 `runSandboxCommand` 和 `createSandboxPreview`。尚未发布面向外部开发者的 TypeScript/Python SDK；PTY、Sessions 和完整 Ports 管理接口尚未公开。当前 HTTP 端口访问由 Previews 接口提供。

## 动作与文件语义

创建及新接受的启停动作返回 `202 Sandbox`。等待时使用响应中的 `revision`，同时检查 `last_action.status` 和目标运行事实；更高 revision 代表原动作被替代。普通名称与 metadata 更新不创建生命周期动作。

删除请求可能返回 `202`，只有 `deletion.completed_at` 才代表清理已确认；已清理后的重复删除返回 `204`。失败不会因为列表隐藏而变成清理成功。

Files 路径限定在 `/workspace`，上传默认覆盖，可传 `overwrite=false`。256MiB 限制、SHA-256 和 Guest 原子提交约束适用于两种运行环境。账号配置和凭证管理只开放给满足权限的会话，不能将普通文件上传当作秘密管理接口。

运行 `npm run generate:openapi` 可重新生成端点页面与分组；`make generate` 执行项目整体生成流程。
