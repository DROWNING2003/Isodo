# API Reference

接口页面由公开 OpenAPI 契约生成，按开发任务分组。网页登录回调、会话管理和 API Key 管理属于账号控制接口，见[认证指南](/docs/guides/authentication)。

## 接口分组

| 分组 | 解决的问题 |
| --- | --- |
| 沙箱管理 | 创建、查询、修改名称、启动、停止和删除沙箱 |
| 应用访问 | 获取沙箱应用入口，以及供客户端打开的应用链接 |
| 安全连接 | 管理持久注入规则；读取规则材料属于敏感操作，需满足该端点的授权条件 |
| 模板管理 | 查看系统与个人模板、修改元数据、设置可见性和派生已有版本 |
| 模板构建 | 提交构建配方、查询构建状态 |
| 模板版本与标签 | 将可变 tag 解析或指向不可变的 Ready build |

## 模板创建与构建

`POST /v1/templates` 只创建模板记录，保存名称、描述和可见性。它不会执行命令，也不会产生可以启动沙箱的镜像。

`POST /v1/templates/{templateID}/builds` 是另一步：提交 `source_build_id`、可选的 `commands` 和 `publish_tag`，登记异步构建任务。配方中的命令使用 argv 数组；需要 Shell 时应显式传入 `/bin/sh` 等可执行程序。

当前公开配方仅接受已有 build 作为来源，没有 Docker/OCI 镜像、Dockerfile 或本地文件上传字段。服务端已有 Registry、队列、状态转换与 Worker 框架；当前生产入口尚未接通执行配方的 Builder，不能将返回 `202` 视为构建已经能够完成。管理员构建、验证和发布系统工件的工具链与此用户构建接口是两条不同流程。本地 Node 另有模板目录和 Lima 命令构建接口，供桌面端使用；它没有接入这里的云端 Build 队列，也不是 Docker 镜像导入接口。

模板、构建和标签的关系是：一个模板可以有多次构建，tag 指向其中一个 Ready build，创建沙箱时将选择固定到具体 build。模板元数据存在，并不代表已有可运行版本。

## 认证与客户端

公开接口需要认证，支持浏览器会话 Cookie、Casdoor Bearer Token 或 API Key。API Key 通过 `X-API-Key` 请求头发送；各端点的具体权限与响应以端点页面为准。

仓库已有生成的 HTTP 客户端与应用内部调用代码，尚未提供经过发布和验收、类似 E2B 的 TypeScript/Python 开发者 SDK。自动生成的 HTTP 请求函数不包含构建等待、命令输出流、文件操作和重连等完整使用体验。

运行 `npm run generate:openapi` 可重新生成端点页面与分组；`make generate` 执行项目整体生成流程。
