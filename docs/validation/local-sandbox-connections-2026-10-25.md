# 本地沙箱连接与 App 路由验证

日期：2026-10-25。范围：本地 Node、T3 派生桌面客户端；没有提交、推送或创建 PR。

## 根因与实现

Guest 的普通执行命令缺省超时为 60 秒。T3 常驻进程启动沿用了缺省值，导致启动后整个进程组被终止；服务端点失效与用户切换页面时间相近，但页面导航不是关闭进程的原因。常驻启动和执行租约过期重试均显式设置 timeout=0。

断开意图写入本机持久化状态；连接注册表启动时保留配对但不自动拨号。重新进入本地沙箱先通过 Node 恢复 T3 服务，再连接已配对环境。业务路由确认账号会话；恢复任务前确认沙箱存在且可用。停止、删除后的连接关闭与普通导航分离。

凭证库模型通过沙箱应用快照同步到对应环境的 provider instance 自定义目录，任务选择器读取已有 T3 设置机制。应用设置复用原有通用、外观和快捷键面板；连接管理使用同一全局 registry，移除配对前明确提示草稿缓存清理。

## 运行证据与边界

- 重建本地 Node 并重启本轮启动的桌面进程后，同一沙箱的 T3 environment 元数据在 0、35、70 秒均返回 HTTP 200 且 JSON 可解析。
- Node 获取沙箱 App 入口后续请求成功，约 0.67 秒。没有在文档中记录认证链接或密钥。
- 前端聚焦测试 11 文件、37 项通过；Web 类型检查通过；新增逻辑 lint 通过。聚焦测试覆盖断开后持久化、页面卸载保留连接、模型目录隔离与选择器可见性、未登录路由、失效沙箱草稿恢复。
- Go orchestrator、localapi、guest/agent 测试通过，覆盖常驻进程无限超时与执行租约过期重试。
- 运行端点检查不等于浏览器点击验证。本轮未操作桌面界面验证 hover、登录跳转和设置面板布局；未调用用户中转站进行新模型推理。
- 原型源码仍有既存未提交改动，交付所需 PR 过程、完整演示和远端验证须另行核对。
