## 关键修复

1. **loopback 未启用**：最小 initramfs/init 没有 `ip link set lo up`，Guest T3 绑定 `127.0.0.1` 后 PortForward dial 报 `network is unreachable`。在 `images/linux-base/isodo-init` 和 `images/t3-base/isodo-t3` 中补上。
2. **过早半关闭**：probe 在 HTTP 请求后立即 `End{Write:true}`，Node/T3 会丢弃 in-flight 请求，表现为 `unexpected EOF`。改为依赖 `Connection: close`，由 T3 自己关闭。
3. **bundle 架构**：`Isodo/app` 默认按宿主架构构建 T3 bundle；Apple Silicon 产物是 arm64，amd64 镜像启动 T3 会 `MODULE_NOT_FOUND @yuuang/ffi-rs-linux-x64-gnu`。已按 `TARGET_ARCH=x64` 重建，并把 `dist/client` 加入 bundle；缺少 `dist/client` 时 T3 返回 `503 No static directory configured`。
4. **内存**：2 GiB 下 T3 约 18–29 秒 Ready；512 MiB 会显著变慢。Cloud `DefaultMemoryBytes` 调整为 2 GiB，`CHVServer` app-link 等待窗口调整为 60 秒，Control 调用 90 秒。

## 未覆盖 / 边界

- 候选使用 jfcs1024 的 5.15 内核，打包时 `ISODO_ALLOW_NO_VMGENID=true`，是冷启动 initramfs，不支持 warm snapshot。
- 未运行公开 API/Preview Gateway 的浏览器端到端；API/Node mTLS 服务和 Preview Gateway 需要单独启动。
- 未发布到 Registry 的最终状态以 `publish-system` 输出为准。
