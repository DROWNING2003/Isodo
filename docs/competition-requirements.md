## 议题与产品方向

- 每个小组根据所属赛组自主选择一个议题，自主完成符合该议题要求的作品。
- 本项目选择的方向：桌面级安全沙箱。安全为核心，其次是最终用户友好性，配置应易于理解和操作。
- 支持在沙箱内运行 Claude Code、Codex、dsh 等主流 Agent 应用。
- 主流 MCP 配置应让用户无需在沙箱内填写 API Key、密码等敏感信息；实现和演示需说明凭证在沙箱外管理、授权和使用的实际链路。
- isodo 以沙箱为第一主体，Agent、任务、文件和连接属于沙箱上下文。产品术语以[产品概念与术语](product-context.md)为准。

## 开发规范与过程记录

1. **每次变更通过 Pull Request 提交。** 实施前确认工作分支及对应 PR，PR 描述说明问题、实现、验证和影响。
2. 保留整个开发期间的真实团队协同或个人创作过程，包括持续的提交与 PR 记录。仅在最后一天一次性提交代码，按赛方要求视为不合格。
3. 团队作品需要真实的多人代码提交记录；提交者身份应对应实际贡献。
4. 允许使用 codebase，但作品必须体现团队在其基础上新增代码的贡献和价值。
5. **使用 codebase 时，录入 codebase 后、任何团队代码产生前，必须给原始基线打 `v0` tag。** 有 codebase 而没有 `v0` tag，赛方将判作品无效并取消资格。
6. `v0` 应指向真实、可核对的原始 codebase 提交，新增贡献应能与该基线比较。已有改动时应先核对原始来源、提交与时间记录，不能把包含团队改动的当前版本当作原始基线。
