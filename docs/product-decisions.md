# 产品决策

本文描述当前实现遵循的产品规则；历史方案通过 Git 历史追溯。

1. **以沙箱为入口。** 任务、文件、安全连接和 Agent 工作台属于沙箱上下文。
2. **同时提供本地和远程入口。** Electron 可选择 Lima 或远程 CHV；Web 面向远程沙箱。具体能力差异见[状态表](current-status.md)。
3. **登录和工具授权分离。** Casdoor + GitHub 登录用于 Isodo 账号；GitHub MCP 使用独立 GitHub App，不互相替代。
4. **收藏、连接、绑定分离。** 收藏便于选择，连接建立账号授权，绑定决定哪个沙箱可以调用。用户移除的连接不能由系统自行恢复。
5. **统一保存沙箱配置。** 安全连接页集中保存选择；新 Agent 任务加载变更，撤销应立即阻止后续 Broker 调用。已有会话读过的信息无法通过撤销抹去。
6. **长期秘密留在沙箱外。** 模型与 MCP 服务端凭证由受保护服务管理；Guest 使用限定沙箱与运行时身份的代理能力。
7. **运行时身份贯穿调用链。** Control 所有权鉴权之后，Node 仍检查生命周期、generation、revision、boot_id 和 guest_epoch。
8. **Guest root 是 VM 内权限。** 新标准模板便于安装开发依赖；不新增宿主机挂载或宿主 root 权限，不放宽公开 Files 工作区边界。
9. **通用 HTTP 预览默认公开。** 每个沙箱端口可持久化切换 private；管理端口禁止预览。T3 工作台保持独立鉴权。
10. **冻结期以稳定演示为目标。** 保留真实限制，不新增商业订阅、跨端快照或大规模界面重构；验收与发布是不同动作。

操作步骤见[路演与冻结检查](roadshow.md)，协议以 OpenAPI 和 Proto 为准。
