# isodo 原型决定

用户已确认访谈范围并授权实现。

- 面向开发和日常任务两类用户；沙箱是第一主体。
- GitHub / Google OAuth 登录入口；登录后进入沙箱总览。
- 多个本地或云端沙箱；用途模板 → 运行位置 → 资源与连接。
- 进入沙箱默认任务工作台，参考用户提供的简洁三栏布局；任务内选择 Agent。
- Agent：Claude Code、Codex、dsh、OpenCode。
- 任务执行、审批、文件产出、终端、应用预览使用 mock 状态。
- 权限参考 T3 四档：监督执行、自动接受编辑、自动、完全访问。Agent 权限受沙箱安全边界约束。
- 账号凭证库统一管理，逐沙箱授权并可撤销。
- 参考 fork.sandbox 的 HTTP 出口代理注入实现：按服务、路径和条件匹配后修改请求头与已有 Query 参数再转发；不因此宣称任意协议密码或所有 MCP 均已兼容。
- 快照保存文件和环境，不含运行中内存；上传后可在云端创建独立沙箱，连接重新授权，不持续同步。
- Free / Plus / Pro；本地基本功能免费，付费主要区别在云端计算、快照存储及保留数量。
- 不提供模型额度，自带模型连接。OpenCode 免费模型作为试用入口方向，具体可用性以服务方为准。
- 中英文切换。
- 登录、运行、上传、付款和权限全部是模拟；不发送 OAuth 请求、不运行命令、不创建真实订阅、不保存真实密钥。

## 沙箱连接与列表交互（2026-10-25）

- 沙箱连接属于应用会话，不随列表、工作台或任务页面的卸载而主动断开；切换沙箱保留其他已配对环境。
- 列表中未连接的沙箱显示“连接”，已有连接显示“进入”和“断开连接”；进入时恢复该沙箱上次的任务页面。
- 显式“暂停并断开”先等待沙箱停止，再关闭对应环境连接，保留配对、任务记录、草稿及磁盘文件；暂停失败时不继续断开。普通页面导航不执行暂停。正常退出桌面应用时，先自动暂停该桌面 Node 管理的本地沙箱，再关闭 Node；macOS 仅关闭窗口不触发暂停。
- 列表、侧栏和工作台共用 TanStack Query 缓存；返回列表先显示缓存，过期后后台刷新。刷新失败保留上次数据，创建、删除及启停成功后更新或失效对应缓存。

## 安全连接的持久与单次规则（2026-10-25）

- 安全连接引用 fork.sandbox 的 injection 语义，分为账号级持久规则和沙箱级单次规则。
- 凭证库（Home）管理持久规则，规则跟随登录用户，可被多个沙箱引用；列表只展示脱敏提示，不返回真实密钥。
- 沙箱内的“安全连接”可以勾选持久规则，也可以新建只属于当前沙箱的单次规则；两类规则合并为同一份有效规则集。
- 本地沙箱的真实注入由宿主侧 HTTPS 代理完成：Guest 只拿到代理地址和 CA 证书，真实密钥不写入沙箱文件或快照。
- 云端沙箱的注入代理尚未接入，界面必须如实提示，不能把已保存规则描述成已生效。

## 凭证库与 Agent 配置设计（2026-10-25）

以下为访谈确认的目标设计，功能实现与运行验证尚未完成。完整流程和验收项见 [凭证库与 Agent 配置设计](credential-library-design.md)。

- 服务连接管理中转站地址、协议和密钥，多份 Agent 配置可复用同一连接；配置支持表单生成与粘贴编辑，沙箱文件使用密钥占位符。
- 模型获取支持搜索、多选、默认模型与手填，选择结果接入 T3 对应 Agent 的任务模型选择器。
- 本地沙箱创建时和运行中均可添加配置及 injection；已有文件保留其他字段，合并冲突展示差异并保留备份。
- 更换 Key 同步更新已授权沙箱的 injection；地址、模型或配置内容变更由用户手动应用；撤销只停用对应 injection。
- 自定义 HTTP 保留 `if_headers`、`if_queries` 多行条件编辑，条件全部满足才注入；支持规则预览。
- 接入范围依据当前 T3 的客户端能力逐项核对，本轮先验收本地沙箱。发现模型和注册驱动均不代表真实请求已验证成功。

## 登录、任务恢复与设置整合（2026-10-25）

- 进入 App 业务路由前确认账号会话；未登录跳转 `/sandboxes/login`，登录与配对回调保留公开入口。会话失效时停止展示业务页面。
- 首页进入沙箱列表；从任务地址刷新时先等待连接目录与沙箱状态，不自动展示属于已删除、已停止或已手动断开的沙箱的草稿。返回列表保留草稿与文件。
- 侧栏页面导航不主动断开连接；显式停止或删除沙箱后关闭对应连接。列表通过卡片进入沙箱，连接管理集中在设置及沙箱侧栏。
- App 设置整合连接、任务分配、通用、外观与快捷键；旧的 T3 连接设置地址转到 App 的连接设置。通用和快捷键提供环境范围选择。
- 应用 Agent 配置时保存该沙箱的模型目录快照；连接后同步到该环境的 T3 provider instance 自定义模型设置。库内编辑不会直接改写其他沙箱；撤销时只移除本功能管理的模型，保留手动模型和其他 provider 设置。
- 本轮未补齐配置文件合并与备份；发现模型、选择模型与真实模型请求成功仍是不同验收项。

## 凭证库统一服务端持久化（2026-10-25）

- Agent 配置、凭证引用、模型目录、默认模型、配置文件模板，以及每个沙箱应用的选择与模型快照均以账号级服务端数据库为权威来源。真实 API 密钥继续使用已有服务端凭证存储。
- 配置文档按 tenant、类别与记录 ID 隔离，使用服务端 AES-256-GCM 加密保存。沙箱 API Key 不允许管理账号配置，引用其他账号凭证的 Agent 配置不能保存。
- 客户端只保留运行时查询缓存。旧 `localStorage` 记录仅作为一次性迁移来源；服务端保存确认后删除迁移副本，失败保留副本并显示错误，不再把加载失败解释为没有 Agent。
- 删除 Agent 配置保留 API 凭证；API 凭证卡可直接创建关联的 Agent 配置。已丢失且未迁移的旧元数据无法从密钥协议可靠推断，不自动补造模型列表。

## 沙箱内临时 Agent 与导航（2026-10-25）

- 沙箱安全连接页保留已配对环境与上次任务上下文；新任务与文件操作继续使用同一沙箱的 project/thread。没有任务时可创建草稿后打开文件，不以页面类型禁用入口。
- 临时 Agent 复用 Agent 配置表单，支持地址、Key、模型、模板及编辑/撤销。它不创建全局凭证库记录；配置、模型与临时材料保存在当前账号的该沙箱加密配置文档中，Guest 配置文件仍只写占位符。
- 保存时一并更新当前沙箱的注入规则与配置文件；撤销临时 Agent 停用对应注入，保留已有文件。与全局 Agent 配置发生文件路径冲突时明确报错，不覆盖另一份选择。
- 安全连接的保存入口为右下角图标按钮，加载及保存期间禁用，保留可访问名称和保存状态。

## 沙箱位置与规格展示（2026-10-25）

- 工作台侧栏本地沙箱使用电脑图标，云端使用云图标，运行位置未知时使用通用沙箱图标。
- 本地沙箱列表接口返回该 VM 在 Node journal 中记录的资源分配；侧栏显示实际 vCPU、内存及磁盘，字节转换为 GiB。未知规格不回填套餐或模板默认值。云端接口尚未提供资源字段时不显示猜测数字。


## 显式暂停与沙箱工作区名称（2026-10-25）

- 侧栏及连接设置里的显式断开操作统一为“暂停并断开”：使用既有本地/云端 stop 生命周期并等待 stopped，再关闭 transport。这里是保留磁盘的停止，不承诺保存 VM 内存或仍在执行的进程。
- 列表执行停止/删除后的连接清理仍使用单纯 transport disconnect，避免重复发起生命周期操作。
- 默认沙箱工作区（包含旧路径）的 `isodo Sandbox` 标题同步为所属沙箱的用户名称，使用现有 T3 project 更新接口持久化，因此顶部、模型输入区项目选择器及欢迎文案使用同一名称。用户自己命名的项目保持原名。


## 退出应用时自动暂停（2026-10-25）

- 正常退出应用先阻止退出，读取桌面 Node 的沙箱所有权索引，向仍活动的本地沙箱发送 stop 并等待 stopped/paused；不枚举或停止第三方 Lima 实例，也不把 base 模板当运行沙箱。
- 等待有上限；停止失败、状态消失或超时不能视为暂停成功。提供重试暂停、取消退出、直接退出三个选项，只有用户明确选择直接退出才绕过未完成的暂停。
- 重复退出请求共用一轮处理。若窗口因未保存内容取消关闭，Node 保持运行；后续再次退出重新检查暂停状态。只有 Electron will-quit 后终止 Node。
- macOS 关闭最后一个窗口继续后台运行；Cmd+Q 或菜单退出才执行此流程。强制结束进程、崩溃或断电不保证执行正常退出钩子。
- 这是保留磁盘的停止/启动流程，不保存运行中进程的内存状态。用户本轮选择保留正在运行的 fenno-test，未重启桌面进程；新构建在下次启动后生效，当前旧进程这次退出仍需手动暂停。


## 工作台精简与技能入口（2026-10-25）

- 移除会话顶部的快捷凭证、项目 Action、Open 编辑器和 Git 操作按钮；凭证管理仍从沙箱安全连接进入。保留会话标题及文件面板等现有工作台能力。
- 我的沙箱列表移除总数/运行中数量摘要，保留位置筛选、搜索和沙箱卡片。
- 账号侧栏与沙箱侧栏新增“Skill”灰色禁用入口，不导航、不发送同步请求。
- 后续目标：账号技能由服务端按账号管理；用户在当前沙箱中选择需要同步的技能，再显式同步到该沙箱。此轮仅保留入口，未实现技能目录、选择与同步。


## MCP 配置与授权方向（2026-10-25）

- Skill 入口统一命名为 Skill；账号与沙箱侧栏增加同样灰色禁用的 MCP 入口。两者后续均按“账号管理、当前沙箱显式选择同步”的交互组织。
- MCP 的 URL、传输类型、认证方式、配置模板与凭证引用纳入凭证库，服务端按账号保存；沙箱同步连接配置与占位符，不同步真实令牌。凭证库已接入静态 Header MCP 的独立类型和管理分区，沙箱可选择授权；Agent 配置自动同步与 OAuth 尚未实现。
- 首先验收 remote Streamable HTTP + API Key/Header，复用 HTTP injection；OAuth 单独增加第三方授权、PKCE、令牌加密保存和刷新，不能用 Isodo 的登录 token 替代上游 token。
- 需要密钥的 stdio MCP 不能通过将真实 Key 写入 Guest 环境变量实现既定 Secretless 目标；首版延后，后续考虑沙箱外的 MCP adapter。
- 当前真实代理 + 本地 HTTPS MCP fixture 的握手、会话头、tools/list、tools/call、SSE 首事件、撤销后的新请求拒绝测试通过；不等同于第三方 OAuth、完整 Agent 客户端或 Guest 真机验证。
