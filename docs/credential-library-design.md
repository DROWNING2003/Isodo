# 凭证库与 Agent 配置设计访谈

状态：已完成第一版本地实现并通过针对性测试；真实 Agent CLI 端到端调用仍待本地目标环境验收。以下区分设计与现有实现。

## 已确认（2026-10-25）

- Agent 配置同时支持表单生成和粘贴配置；默认使用表单，高级入口支持粘贴、编辑和预览。
- 中转站地址、协议和密钥由可复用的服务连接管理；多个 Agent 配置引用同一服务连接，换 Key 只需修改连接。
- 获取模型失败时允许手填模型名。
- Agent 接入范围跟随当前 T3 支持情况；Google Antigravity 暂缓。
- HTTP 默认显示名称、目标地址、认证方式和密钥；保留 `if_headers`、`if_queries`，放入高级设置。认证方式提供 Bearer Token、API Key Header、自定义 Header。
- 同一沙箱内同一 Agent 的多份配置切换不纳入本轮设计。
- 用户目标：授权沙箱时放入 Agent 配置文件，API Key 使用占位符，通过用户对应的 injection 注入真实密钥。HTTP 提供用户自定义入口。
- 在沙箱中选择并授权 Agent 配置时，同时写入配置文件并绑定 injection；创建时可以选择，使用中也可添加凭证和 injection。
- 已有配置保留其他字段，只更新本次管理的连接、模型和认证字段；无法安全合并时展示差异，由用户决定是否覆盖，并保留备份。
- 粘贴配置含真实 Key 时，识别后显示脱敏确认，将密钥保存到服务连接，配置中替换为占位符；无法识别的认证字段由用户指定，沙箱配置预览只展示占位符。
- 服务连接更换 API Key 后，同步更新已授权沙箱的 injection，后续请求使用新 Key。
- 地址、模型或配置内容变更时，沙箱提示有配置更新，由用户应用后合并；需要重启 Agent 才能加载时明确提示。
- 沙箱撤销授权只停用对应 injection，配置文件保留。
- 本轮先完成本地沙箱的实际验收，覆盖运行中授权、配置写入、Agent 经 injection 访问中转站和撤销失效。
- 获取模型后支持搜索、多选和指定默认模型；选中的模型接入对应 Agent 的 T3 任务模型选择器。获取失败仍可手填；发现模型不代表协议兼容已验证，需通过连接测试确认。
- `if_headers`、`if_queries` 支持多行键值条件的增删；同一规则的条件全部满足才注入，留空表示不增加该类条件限制。
- Agent 配置自动生成对应占位符匹配条件；自定义 HTTP 由用户填写，并可预览完整匹配规则。

## 当前实现核对

- HTTP 凭证由 `InjectionRuleDialog.tsx` 编辑；Header/Query 条件编辑能力需继续按已确认设计核对。
- 账号 API 保存凭证、Agent 配置与模型目录，以及沙箱应用选择和模型快照；配置文档按账号加密存储，客户端只保留查询缓存。旧 localStorage 仅用于一次性迁移。界面支持使用未保存的 Endpoint、协议和 Key 获取模型。
- 旧 TS sandbox-client 存在 Codex 配置与占位 auth 文件生成先例，不能据此认定当前凭证库已接入该链路。
- `docs/secure-connections.md` 记录本地 Lima curl 注入已验证，云端代理尚未接入，Agent CLI 实际注入仍待目标环境验收。本次为只读核对，未重跑运行验证。
- deepseek-harness 的 `CustomProviderCard.tsx` 与 `ModelListEditor.tsx` 支持使用未保存的连接草稿获取模型、搜索勾选、失败后手填；可借鉴该交互，但它不是沙箱配置文件生成器。
- 当前 `app/apps/server/src/provider/builtInDrivers.ts` 注册 Codex、Claude、Cursor、Grok、OpenCode、Antigravity。驱动注册不等于对应客户端已支持任意中转站或已在沙箱验收；具体配置能力需逐项核对。

## 当前实现状态（2026-10-25）

### 已实现

- 凭证库支持创建和编辑 Agent 配置，支持 Codex、Claude Code、OpenCode、Cursor、Grok；同一表单直接填写 Endpoint、协议、API Key，保存时创建凭证并关联配置，也可选填已有凭证。
- 配置支持使用未保存的接口草稿获取模型、搜索、多选、默认模型和失败后手填；手动添加自动选中。OpenAI 使用 `/models`，Anthropic 使用 `/v1/models` 和对应认证 Header。模型发现仍由 renderer 发起，服务端跨域限制可能导致获取失败；真实中转站请求尚未验收。
- 高级配置支持粘贴和编辑；识别到常见 Bearer、API Key、Token 字段或已知密钥时，保存内容会替换为 `${ISODO_SECRET}` 占位符。
- 桌面端本地 Node 新增 Agent 配置写入 API。写入内容仅接受脱敏配置，路径限制在沙箱 home 的受控配置目录或 workspace，并通过 Guest `WriteFile` 原子写入，返回路径、SHA-256、字节数和重启提示。
- 沙箱“安全连接”页可选择 Agent 配置；应用前要求对应服务连接已授权，然后写入配置文件并复用该连接的 injection。

### 已验证

- Web Agent 配置占位符、粘贴脱敏、模型响应解析和模型地址拼接测试通过。
- Node local API、路径遍历拒绝、占位符写入、orchestrator 相关 Go 测试通过。
- 前端本轮涉及文件的 TypeScript 检查无新增错误；仓库已有 Effect 建议诊断仍存在。

### 仍待本地目标环境验收

- Codex、Claude Code、OpenCode、Cursor、Grok 的真实配置文件格式、中转站协议兼容性和模型调用需逐项运行验收。
- 运行中添加配置、真实 Agent 经 injection 访问中转站、换 Key 后旧 injection 失效、撤销后的请求失败，需要在 Lima 本地沙箱中完成真实验收记录。
- 服务端持久化的 Agent 配置表、跨设备同步、配置差异合并/备份和 T3 任务模型选择器接入尚未完成。
- 云端沙箱的配置写入和注入代理仍未接入；Google Antigravity 暂不支持。

1. 凭证库新建时选择 Agent 配置或自定义 HTTP。
2. Agent 配置选择对应 Agent，填写或复用服务连接；可通过表单生成，也可粘贴、编辑和预览配置。
3. 使用连接草稿获取模型，搜索、多选并指定默认模型；也可手填。保存配置时将真实 Key 与含占位符的配置内容分开。
4. 在本地沙箱创建时或运行中选择并授权配置，写入配置文件并绑定 injection；已有文件按已确认的合并与冲突处理方式处理。
5. T3 任务选择对应 Agent 和已配置模型；真实模型调用与撤销失效必须在本地沙箱验证。
6. 换 Key 更新 injection；其他配置变更由用户应用。撤销只停用对应 injection。

## 实现与验收检查

- 核对当前 T3 的 Codex、Claude、OpenCode、Cursor、Grok 各自的配置、模型注册及中转站兼容能力；驱动注册与客户端可用性分开报告。
- 为服务连接、Agent 配置及沙箱授权建立持久数据关系，并保留当前 HTTP 持久与单次规则的使用能力。
- 配置写入、injection 绑定和模型注册的各阶段应返回真实状态；部分失败不能显示为配置已可用，保留可重试和错误定位信息。
- 同一中转站的不同凭证使用可区分的占位符条件，验证不会串用真实密钥。
- 验证配置合并、真实 Key 不进入沙箱文件、模型列表失败回退、运行中添加、Key 更新、手动应用配置变更和撤销失效。
- 文档区分已实现、已验证与仍未支持的 Agent 能力。


## 凭证库交互修正（2026-10-25）

- 新建 Agent 默认直接填写 API 地址、协议和 Key，填写途中无需跳转到另一张“服务连接”表单；已有凭证仅作为可选填入入口。
- 获取模型直接使用草稿，保存失败保留输入；服务端 Agent 配置保存凭证引用和脱敏配置模板；应用到沙箱的配置文件只使用密钥占位符。
- 页面按 Agent 配置与独立 HTTP 凭证展示，隐藏被 Agent 引用的重复凭证卡片；显示地址、模型和授权情况，删除底层持久规则和 injection 说明。
- 配置路径及粘贴配置收进高级设置。现有配置可直接修改 API 地址和 Key；引用同一凭证的其他配置也会受影响，编辑时明确提示。
- 实际桌面视觉与真实中转站请求尚未验证。

## 保存失败排查与修正（2026-10-25）

- 运行中的旧 API 对 `/v1/injection-rules` 返回纯文本 404；同一进程的 `/v1/sandboxes` 返回正常的未认证 401。数据库 `injection_rules` 表已存在。
- 经用户授权重新编译、重启 API 后，凭证接口返回正常的未认证 401，确认路由已注册。未使用用户登录凭证进行真实保存，认证后的页面保存仍需用户实际重试。
- 凭证集合接口缺失时显示明确的 HTTP 404 与重启提示；页面保留具体加载错误，并提供重新加载按钮。
- Agent 保存错误移到固定页脚的按钮旁，避免被表单滚动区域遮住。
- 添加按钮移到对应分区标题旁；Agent 和 HTTP 空状态共用同一个组件。加载失败时不再将 HTTP 凭证显示为空集合。

## 沙箱凭证选择与创建选项（2026-10-25）

- 沙箱内直接勾选 Agent 配置和独立 HTTP 凭证，一次保存完成凭证授权及所选 Agent 文件写入；移除原先重复的“持久化规则 / 应用配置”两步操作与代理实现说明。
- 创建沙箱新增默认折叠的“更多选项”，本地沙箱可选凭证；VM Ready 后应用所选配置，再连接 T3。不选凭证时沿用原创建流程，云端明确标记暂不支持。
- VM 已创建但凭证应用失败时保留其 ID，重试继续配置该 VM，不重复创建。
- 保存成功立即更新本地查询缓存；后台统计刷新不再阻塞保存返回。读取材料、写授权和写文件分阶段显示进度，并有超时反馈。授权已保存但文件失败时明确显示部分成功。
- 先校验配置是否存在、目标路径是否冲突。自动生成 Codex 配置与占位 auth.json、Claude settings、OpenCode provider 配置；Cursor/Grok 尚需提供配置内容。模型网关的客户端协议兼容性仍需逐项实际验收。
- 每个服务连接使用独立占位符匹配认证 Header，避免同一地址上不同 Agent 凭证互相混用；保留用户其他匹配条件。
- 修正 Codex 配置路径为 T3 的真实 CODEX_HOME `/workspace/.codex`。其他 home 配置仍位于 `/workspace/.home`。
- 验证：24 项前端定向测试通过；orchestrator、localapi、injection Go 测试通过；已构建并经用户授权重启桌面应用。本地 Node 临时规则 PUT/GET/DELETE 成功，PUT 约 2 ms；真实 Guest 临时文件验证 Codex 路径正确，测试规则和文件已清理。没有使用用户真实 Key 请求中转站。
- 完整的已有配置差异合并与备份、T3 模型选择器动态目录仍需后续补齐，不能把当前文件写入描述为已完成这些能力。

格式核对参考：[Claude Code 凭证环境变量](https://support.claude.com/en/articles/12304248-manage-api-key-environment-variables-in-claude-code)、[OpenCode providers](https://docs.opencode.ai/docs/providers/)。Codex 文件沿用仓库现有 `buildCodexConfigToml` / `buildCodexAuthJson` 的配置及认证方式，并使用用户选择的模型与 Endpoint。
