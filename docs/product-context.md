# 产品概念与术语

Isodo 以沙箱为第一主体。当前实现与真实验收边界见[能力状态](current-status.md)。

| 概念 | 含义 |
| --- | --- |
| 沙箱 | 拥有独立运行时身份、系统盘与持久工作盘的环境；本地使用 Lima，远程使用 CHV |
| 工作台 | 沙箱内 Agent 的任务、文件和终端界面，通过经过授权的应用链接访问 |
| Agent 配置 | 模型连接及运行参数；长期凭证由沙箱外的受保护服务管理 |
| 任务 | 工作台中的一次 Agent 会话；配置更新通常由新任务加载 |
| MCP | Agent 调用外部工具的协议；市场提供官方连接和自定义 HTTPS 服务 |
| 收藏 | 将市场条目加入个人选择列表，本身不授予沙箱访问权 |
| 连接 | 账号已完成第三方授权，或保存自定义服务连接配置 |
| 绑定 | 用户明确允许指定沙箱使用某个连接或 Skill |
| Skill | 包含 SKILL.md 指令的技能；收藏后可选择应用到远程沙箱 |
| 端口预览 | 通过 Gateway → Node → Guest 访问服务，通用 HTTP 默认 public，可切换 private |
| 模板 / Build / Tag | 模板是元数据，Build 是不可变构建工件，Tag 是可变引用 |

停止沙箱会保留工作盘，启动重新建立运行时身份；这不等于承诺恢复原进程和内存。删除完成以 API 的清理确认字段为准。

新标准模板内使用 Guest root；权限限于 VM，不授予宿主机 root。公开 Files API 仍限制在 /workspace。旧沙箱不会因升级自动更换镜像或用户。

产品级快照跨端流转、商业订阅及公开 PTY/Processes API 不属于当前完整交付能力；内部模板恢复机制不能替代这些产品能力。当前本地市场 MCP/Skill 接线与远程能力有差异，不承诺两端完全一致。
